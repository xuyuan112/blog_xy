# frontend-firefly 重构范围基线

状态：任务 1（重构目标与边界）已执行。

## 唯一业务来源

前台业务只允许调用：

`F:\个人博客\blog-parent\blog-web\blog-web-app`

统一 API 前缀为 `/xuyuan`，统一响应为 `R<T>`。前端不得再把本地 Markdown、Firefly 示例数据或第三方页面作为文章/杂谈的业务数据源。

## 保留业务

- 首页、文章列表、文章详情
- 杂谈列表、杂谈详情
- 分类、标签、时间线归档
- 全站搜索
- 相册、相册详情、照片 EXIF
- 友链、友链申请
- 关于页
- 公告、一言、天气、日程
- 评论、点赞
- 前台用户登录、注册、刷新 token、退出、修改密码

## 删除业务

- Bangumi、VNDB、MyAnimeList
- 书签导航
- 赞助页
- 系列页
- 旧动态 Markdown 业务（迁移为后端 thoughts）
- 与上述功能绑定的配置、组件、生成器和示例数据

## 主导航契约

```text
首页 /    文章 /posts/    杂谈 /thoughts/    归档 /archive/
相册 /gallery/    友链 /friends/    关于 /about/    搜索 /search/
```

认证入口属于用户操作，不占用主导航固定位置。

## 不可违反的边界

1. 不修改 `blog-parent` 后端代码来适配旧前端字段；字段差异在 `frontend-firefly/src/lib/api` 内解决。
2. 不在页面组件中直接拼接后端 URL；统一使用 API client。
3. 不在删除旧页面前删除通用 Markdown、图片、分页、评论、点赞和认证能力。
4. 不把 SSR 页面误发布为只有静态 `dist` 的站点；生产必须验证动态路由和 `/api/*`。
5. 每个阶段完成后运行 `pnpm check`、`pnpm type-check`、`pnpm build`，失败时停止删除动作。
6. 旧壁纸系统、侧栏布局和浮动控制必须保留，包含其运行时切换和移动端行为；清理旧业务时不得删除这些公共布局能力。
