## MySQL Access denied 真因
- 用户手动 `mysql -h 127.0.0.1 -ublog` 可连通，但后端 jar 打包的 application-local.yml 连 192.168.10.103，MySQL 反向解析来源为 server01，MySQL 里只有 localhost/127.0.0.1 的 blog 用户 → host 不匹配导致拒绝。
- 修复: `CREATE USER 'blog'@'%' IDENTIFIED BY 'Xy20041102.'; GRANT ALL ON blog.* TO 'blog'@'%'; FLUSH PRIVILEGES;`

## 部署最终落地方案（已验证）

### 文件三件套（无 node_modules）
服务器只需要这 3 个东西，不需要 npm install / npm run build：
1. `dist/` —— vite build 出来的产物
2. `serve.cjs` —— 零依赖静态服务器 + /xuyuan 反向代理
3. `package.json` —— 仅用于让宝塔读 `scripts.start`

### serve.cjs 关键逻辑
- 路径以 `/xuyuan/` 开头 → 转发到 BACKEND_URL（默认 http://127.0.0.1:8080）
- 其他路径 → 读 dist 静态文件，不存在 fallback 到 index.html（SPA）
- 监听 0.0.0.0:5174，可被 PORT/HOST 环境变量覆盖
- 用 `node:http` 内置模块，零第三方依赖

### VITE_API_BASE_URL 必须留空（不能填 /xuyuan）
原因：源码 `request.ts` 里：
```js
const apiBaseUrl = (import.meta.env.VITE_API_BASE_URL || '').replace(/\/$/, '')
function createService(baseURL) {
  return axios.create({ baseURL: `${apiBaseUrl}${baseURL}` })
}
export const authService = createService('/xuyuan/auth')  // 内部硬编码 /xuyuan
```
- 留空 `''` → baseURL = `/xuyuan/auth` ✅ 浏览器请求 `/xuyuan/auth/captcha`
- 填 `/xuyuan` → baseURL = `/xuyuan/xuyuan/auth` ❌ 后端接 `/xuyuan/xuyuan/auth/captcha`，触发 NoHandlerFound
- 填 `http://IP:8080` → baseURL = `http://IP:8080/xuyuan/auth` ⚠️ 跨域，需要后端 CORS

### 宝塔 Node.js 命令行版本默认是「未设置」
这是宝塔"Node.js 版本管理器"的一个隐藏坑：装 Node 时系统级有，但命令行版本下拉框默认 "未设置"，导致 SSH 里 `node`/`npm` 都找不到。
修法：宝塔面板 → 软件商店 → Node.js 版本管理器 → 命令行版本选实际安装的版本（如 v24.20.0） → 保存 → 重连 SSH。

### build 命令跳过 vue-tsc
production build 不做类型检查（类型检查放本地）。
原 `package.json`："build": "vue-tsc --noEmit && vite build" 会因为宝塔 npm install 没装 devDependencies 失败。
改成 "build": "vite build"，把 vue-tsc 留给本地 npm run build:full 跑。

### 端口放行清单（公网必须）
- 阿里云 ECS 安全组：5174/8080/8081 入站放行（TCP 0.0.0.0/0）
- 宝塔防火墙：同样放行
- 6379 只对 127.0.0.1/32（Redis 严禁对外）
- 3306 看情况（MySQL 看是否需要远程连）
- 9000/9001 MinIO 同理（最好对内）

### 反向代理的两条等效路径
1. **生产常用**：nginx `location /xuyuan/ { proxy_pass http://localhost:8080; }`
2. **本项目用**：serve.cjs 内置 pipeProxy，零依赖
两者机制一样，浏览器从头到尾只看到同一个 origin（同源），没有跨域问题。

### 调试路径
- 浏览器 F12 → Network → 看请求 URL
- 必须看到 `公网IP:5174/xuyuan/xxx`，不是 `localhost:8080/xuyuan/xxx`
- 404/timeout → 多半是路径前缀错了
- 403 → 后端 CORS 没配（方案 A 是把请求走同源避免）
