## 一、Context（背景与动机）

当前根目录下只有一个前端项目 [blog-ui](file:///f:/个人博客/blog-ui)，其中混放了前台展示页（home/moment/gallery/archive/thought/friend/about 共 7 个视图）和后台管理占位页（`views/admin/AdminView.vue` 仅显示"后续接入管理端功能"）。后端早已按 [blog-web-admin](file:///f:/个人博客/blog-parent/blog-web/blog-web-admin)（端口 8080）+ [blog-web-app](file:///f:/个人博客/blog-parent/blog-web/blog-web-app)（端口 8081）拆成两个独立 Spring Boot 模块，前端架构不对称。

### 拆分目标

| 维度 | blog-web-ui（前台展示端） | blog-admin-ui（后台管理端） |
|---|---|---|
| 角色 | 面向访客的阅读型站点 | 面向博主的管理控制台 |
| 对接后端 | blog-web-app @ 8081 | blog-web-admin @ 8080 |
| 技术栈 | Vue 3 + Vite + TS + Element Plus + Pinia | 同左（手写 Pure Admin 精简版风格） |
| 首期范围 | 清理 admin 占位代码，修正端口 | 骨架 + 登录页 + JWT 鉴权链路 + 主布局 + 仪表盘 + 文章管理 |

### 现状盘点（关键发现）

1. **端口配置反了**（潜在 bug）：当前 [blog-ui/.env.development](file:///f:/个人博客/blog-ui/.env.development) 把 `VITE_API_BASE_URL` 标注为"前台 blog-web = 8080"，`VITE_ADMIN_API_BASE_URL` 标注为"后台 blog-admin = 8081"；[vite.config.ts](file:///f:/个人博客/blog-ui/vite.config.ts) 的 proxy 也按此注释。但后端 [application.yml](file:///f:/个人博客/blog-parent/blog-web/blog-web-admin/src/main/resources/application.yml#L1-L2) 实际是 admin=8080、app=8081。拆分时必须修正。
2. **通用基础设施可复用**：`utils/request.ts`、`types/api.d.ts`、`stores/user.ts`、`styles/index.scss`、`main.ts`、`App.vue` 都是标准 Vue 3 + Element Plus 脚手架代码，两个项目都需要一份。
3. **前台 API 模块（5 个）留在 blog-web-ui**：`article.ts`、`archive.ts`、`gallery.ts`、`moment.ts`、`site.ts`。
4. **后台 API 模块（2 个）迁移到 blog-admin-ui**：`admin.ts`（文章管理 + 仪表盘）、`auth.ts`（验证码/登录/刷新/登出/用户信息）。
5. **components 目录为空**，无需迁移。

### 3.2 核心模块设计

#### 3.2.1 [src/utils/request.ts](file:///f:/个人博客/blog-ui/src/utils/request.ts)（精简版）

```typescript
import axios, { type AxiosInstance, type AxiosRequestConfig, type AxiosResponse } from 'axios'
import { ElMessage } from 'element-plus'
import type { ApiResult } from '@/types/api'

const clientType = 'admin'

function createService(baseURL: string): AxiosInstance {
  const service = axios.create({ baseURL, timeout: 15000 })

  service.interceptors.request.use((config) => {
    const token = localStorage.getItem('accessToken')
    if (token) config.headers.Authorization = `Bearer ${token}`
    config.headers['X-Client-Type'] = clientType
    return config
  })

  service.interceptors.response.use(
    (response: AxiosResponse<ApiResult>) => {
      const { code, message, data } = response.data
      if (code === 200) return data as never
      if (code === 401 || code === 601 || code === 602) {
        // 601/602 = token 失效/过期（按 API_SPEC 三位数业务码）
        clearTokensAndRedirect()
        return Promise.reject(new Error(message))
      }
      ElMessage.error(message || '请求失败')
      return Promise.reject(new Error(message))
    },
    (error) => {
      const status = error.response?.status
      if (status === 429) ElMessage.error('操作过于频繁，请稍后再试')
      else ElMessage.error(error.message || '网络错误')
      return Promise.reject(error)
    }
  )

  return service
}

export const adminService = createService('/xuyuan/admin')
export const authService = createService('/xuyuan/auth')

export function request<T = unknown>(service: AxiosInstance, config: AxiosRequestConfig): Promise<T> {
  return service.request(config) as Promise<T>
}

// 后台快捷方法（统一前缀 /xuyuan/admin）
export const adminGet = <T = unknown>(url: string, params?: object) =>
  request<T>(adminService, { method: 'get', url, params })
export const adminPost = <T = unknown>(url: string, data?: object) =>
  request<T>(adminService, { method: 'post', url, data })
export const adminPut = <T = unknown>(url: string, data?: object) =>
  request<T>(adminService, { method: 'put', url, data })
export const adminDel = <T = unknown>(url: string, params?: object) =>
  request<T>(adminService, { method: 'delete', url, params })

// 认证快捷方法（统一前缀 /xuyuan/auth）
export const authGet = <T = unknown>(url: string, params?: object) =>
  request<T>(authService, { method: 'get', url, params })
export const authPost = <T = unknown>(url: string, data?: object) =>
  request<T>(authService, { method: 'post', url, data })

function clearTokensAndRedirect() {
  localStorage.removeItem('accessToken')
  localStorage.removeItem('refreshToken')
  if (location.hash !== '#/login') location.hash = '#/login'
}
```

#### 3.2.2 [src/permission.ts](file:///f:/个人博客/blog-ui/src/router/index.ts)（路由守卫）

```typescript
import { router } from '@/router'
import { useUserStore } from '@/stores/user'

const WHITE_LIST = ['/login']

router.beforeEach((to, _from, next) => {
  const userStore = useUserStore()
  document.title = (to.meta?.title as string) ? `${to.meta.title} - 后台管理` : '后台管理'
  if (userStore.accessToken) {
    if (to.path === '/login') next('/')
    else next()
  } else {
    if (WHITE_LIST.includes(to.path)) next()
    else next(`/login?redirect=${encodeURIComponent(to.fullPath)}`)
  }
})
```

## 六、风险与权衡

| 风险 | 缓解 |
|---|---|
| 手写 Pure Admin 精简版缺少标签栏/主题切换/虚拟表格等高级功能 | 个人博客体量足够，首期核心是登录+主布局+仪表盘+文章管理，这些功能用 Element Plus 原生组件即可实现 |
| 后端 M1（JWT 鉴权链路）未实施，登录/仪表盘 API 可能 404 | 前端先用 mock 数据验证 UI；后端 M1 完成后联调。`utils/request.ts` 的 401 处理逻辑提前就位 |
